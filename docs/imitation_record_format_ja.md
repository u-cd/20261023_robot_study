# 模倣学習データの保存形式と確認結果

確認日：2026年10月31日（日本時間）。確認時点のスナップショット。追加収集中のため件数は今後変わる。

成功例 **27試行・4,534操作区間**。連続JOGは3,802区間、従来方式は732区間。

## 確認したこと

- 全試行で3段階（0：つかむまで、1：はなすまで、2：退避）の記録あり。
- メタデータの件数と結果行数・連番が一致。参照画像のファイル欠損なし。
- 操作前後の指令差とdelta_degが一致。他関節の意図しない指令変化なし。
- 画像時刻が指令時刻より未来になるサンプルなし。
- これは保存データの整合性確認。実角度・実位置・把持成功をセンサーで確認した結果ではない。

画像撮影から指令までの時間は中央値38.4ms、最大193.4ms。連続移動の1区間は中央値113.5ms、最大240.7ms。固定周期ではない。

## 1試行のフォルダ

```text
data/imitation/<UTC日時のエピソードID>/
  episode.json       開始条件・初期関節指令・段階定義・成否・件数
  setup.jpg          開始時の元画像
  frames/000000.jpg  操作区間の開始に対応する元画像
  samples.jsonl      操作区間の構造化記録（1行＝JSON）
  viewer.html        画像と操作ラベルを目視する一覧
  features.json      保存画像を後処理して生成する検出結果・学習入力
```

動画ではなく操作に対応した静止画像列。無操作中の連続映像は保存しない。画像にはライブ表示用の検出枠・文字を焼き込まない。

## samples.jsonl の1区間

| 項目 | 意味 |
| --- | --- |
| index / image | 操作番号と対応する画像の相対パス |
| phase | 0：つかむまで、1：はなすまで、2：退避 |
| frame_captured_at / frame_sequence | 撮影UTC時刻とカメラ側フレーム番号 |
| state_before | 区間開始側の全5関節の指令角度、目標、保持、速度 |
| command_sent_at / acknowledged_at | 指令送信・応答のUTC時刻（連続移動） |
| action / joint / direction | 操作する関節と増減方向 |
| control_mode | jog：連続移動区間。省略時は従来のstep方式 |
| state_after | 次回更新または停止で確認した区間終了側の指令 |
| delta_deg | 操作関節の終了指令−開始指令。実測角度ではない |
| interval_seconds | 連続移動区間の経過秒数。固定時間ではない |
| dt_since_previous_action_s | 直前の指令送信からの時間差。考えていた時間も含み得る |
| accepted | 通信・指令状態による記録の受理。物理的成功の判定ではない |

連続移動では、長押しを数区間に分割し、次回更新・STOPの時点で前区間の変化量を確定して非同期保存する。従来stepではintent（送信前）とresult（結果）の2行があるので、学習時はaccepted=trueのresultだけを読む。

開始姿勢はepisode.jsonのinitial_state、各操作の現在姿勢はstate_beforeに保存。画像と状態の取得は同時刻を保証するハード同期ではない。撮影・状態・送信時刻を残し、その差を評価できる形にしている。

## 検出結果と学習入力

確認時点ではfeatures.jsonがあるのは2試行・472サンプル。残る25試行は元画像・操作記録が保存済みで、検出特徴の後処理は未実施。ライブ検出の表示だけではこのファイルは生成されない。

features.jsonは、画像ごとの検出枠（ピクセル）、正規化中心座標、信頼度、検出有無、操作番号・撮影時刻との対応、モデル重みSHA256・推論設定を保存する。coinの内部クラス名は既存モデルに合わせてtarget。表示名はcoin。

入力15項目＝スポンジ・コイン中心4＋信頼度2＋検出有無2＋関節指令4＋段階one-hot3。方向9クラスのlabelに加え、delta_deg・interval_secondsも抽出する。連続移動と従来stepの教師を一律1°として扱わない。方策の学習・実機での自動実行はまだ行っていない。
