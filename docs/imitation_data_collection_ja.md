# 人がアームを操作して実演を集める

## 最優先の方針

**実際に何度もアームを操作した生データを十分に保存し、工程別・関節別の教師データは後処理で作る。元の操作記録・画像を、現在の工程設計に合わせて不可逆に加工しない。** 既存27成功試行もローカルに保持する。

現行形式には操作区間に対応した静止画像列があるが、無操作中を含む連続動画ではない。ACT向けの一定周期の収集への改善は、既存記録を維持したうえで別に検討する。

## 起動

```bash
uv run python control/arm_panel.py
```

別ターミナル：

```bash
uv run python vision/arm_camera_panel.py
```

<http://127.0.0.1:8766> を開く。紙・校正・運動学モデルは不要。カメラの識別子と解像度は `configs/camera.json` で指定する。検出枠が必要ならカメラサーバーに `--detections` を付ける。

## 操作

1. ポートを指定して接続し、実物の姿勢を確認してから全5関節を有効にする。手首は80°。
2. スポンジとcoinを届く位置へ置き、必要なら配置条件をメモする。
3. 「デモ記録開始」。開始画像と全関節の指令状態を保存する。
4. 記録専用の矢印で操作する。長押しは連続移動、微調整モードは1°。離す・フォーカスが外れると連続指令を停止する。
5. 必要な境界で段階を切り替える。段階は追加情報として記録され、操作を細かく制限するルールではない。
6. 搬送と退避まで終わったら「成功して保存」。各段階の終了ごとに別の成功試行として保存するわけではない。

段階は「つかむまで」「はなすまで」「退避」の3つ。現行の小型ACTの入力には、この段階ラベルを使っていない。

成功試行は `data/imitation/試行ID/` に保存する。失敗・中断は、以前のユーザー指定により、その試行だけ破棄する。記録中にカメラサーバーを終了した場合も中断扱い。この仕様を変えるときは、生記録を残す方針とは別に検討する。

## 残すもの

元画像、開始条件、操作前後の全関節指令、操作方向・変化量・速度設定、撮影・送信・終了時刻、試行ID、段階、成功結果を対応づける。関節角度は実測値ではなく指令値。

生画像・操作ログはGit管理外。検出結果や学習用の分割・正規化・再サンプリングは派生物として扱う。カメラ位置やアーム位置を変えた場合は、条件の違いを記録する。
