# 模倣学習の手動デモを集める

[保存形式の詳細とデータ確認結果](imitation_record_format_ja.md)

2026年10月31日。記録UIとオフライン特徴抽出を実装。方策の学習・自動操作はまだ行わない。

## 起動

プロジェクト直下で、別々のターミナルから起動する。すでに起動している場合は二重起動せず <http://127.0.0.1:8766> を再読み込みする。

```bash
uv run python control/arm_panel.py --record-calibration
```

```bash
uv run python vision/arm_camera_panel.py
```

終了は各ターミナルでCtrl+C。カメラ側を通常終了した場合、記録中のデモは中断として削除する。強制終了・電源断時の `recording` のままのデモは成功例にしない。

## ライブ検出

画面表示中はYOLO11nでスポンジ（緑）とコイン／ターゲット（紫）を継続検出する。枠と信頼度は推論した同じフレームに描画する。校正の青い外枠・黄色い十字は表示しない。記録用の元画像は描画なしで保存し、学習用の検出結果はこれまで通り記録後に抽出する。

## 最初の1回

1. スポンジと黒いターゲットを無理なく届く位置に置く。カメラと台座は固定する。
2. 通常操作欄で接続し、姿勢を確認して全5関節を有効にする。手首は80°に揃える。開始姿勢は毎回同一でなくてよいが、最初は慣れた姿勢で試す。初期値への有効化で急に動く場合があるため、現在の姿勢に合う値を使う。
3. 上部「模倣学習：手動デモ記録」に配置などのメモを入れ、**デモ記録開始**を押す。開始操作そのものはアームを動かさない。
4. 「今から行う段階」を選び、記録用の台座・肩・肘・グリッパーの矢印で操作する。通常は長押しで連続移動し、離すとSTOPを送る。細かい位置合わせは「微調整（1°）」へ切り替える。手首は動かさない。
5. 作業が切り替わる**前**に段階を変更する。下降は台座→肘→肩、上昇は肩→肘→台座という実機で扱いやすかった順番を人が選ぶ。グリップを無理に150°まで閉じる必要はない。
6. 物理的に待つ必要がある場面では「必要な待機を記録（0.2秒）」を押す。考えている時間や段階選択の時間は自動で待機ラベルにしない。
7. 運べたら「成功して保存」。失敗したら「失敗して破棄」、途中でやめる場合は「中断して破棄」。画像・操作記録を含めて試行フォルダごと削除する。操作中の場合は、操作が完了してから終了ボタンを押す。
8. 表示された保存先の `viewer.html` をブラウザで開き、操作直前画像とラベルを確認する。まず1回の記録を確認してから、配置を変えて5〜10回程度集める。これで十分な学習精度が出るという意味ではない。

記録中は8766の記録用矢印だけを使用する。同じ画面の通常操作・搬送操作はサーバーで拒否する（状態確認・停止は可能）。8765を別タブで操作したり、別スクリプトから指令を送らない。現在の仕組みでは別経路の操作を完全に封鎖できない。

## 3段階

1. **つかむまで**：接近、グリップを開く、下降、微調整、グリップを閉じてつかむまで。
2. **はなすまで**：持ち上げ、搬送、下降、置く位置への微調整、グリップを開いてスポンジを離すまで。
3. **退避**：スポンジを離した後、アームを退避する。

スポンジをつかめたら2へ、スポンジを離し終えたら3へ切り替える。下降中の位置合わせなどは同じ段階のまま自由に行う。段階は関節を動かす順番を強制するものではない。

段階は人が付ける教師ラベル。今後の方策で段階を入力する場合、段階切り替えを別に用意する必要があり、AIが段階判断まで学んだことにはならない。実際に必要な段階の操作だけ記録する。

## 保存内容

`data/imitation/<エピソードID>/` に保存する。このフォルダはGit管理外としてローカルに保持する。画像と操作ログは再生成できないため、必要なバックアップはGitとは別に用意する。

- `episode.json`：開始条件、カメラ、開始指令、段階名、結果、メモ、操作件数。
- `setup.jpg`：開始時のカメラ画像。
- `frames/000000.jpg` など：各操作の**直前**画像。枠や文字を焼き込まない。
- `samples.jsonl`：操作意図と結果を別行で追記。撮影時刻・フレーム番号、操作前後の全関節指令、速度、段階、送受信時刻、指令間隔、受理確認、エラー。
- `viewer.html`：終了時に生成する画像と操作の一覧。
- `features.json`：下のコマンドで後から生成する検出特徴と学習用入力。

1°微調整は状態確認→新規画像→状態再確認→画像と操作意図の保存→1°指令→結果保存の順。連続移動は下記の非同期保存方式を使う。画像を取得できなければ移動を継続しない。関節値は**指令値であり実測角度ではない**。同じ指令で保持していても物理的に静止した保証はないので、実機を見て操作する。

今回は操作ごとに記録するBC用データ。固定FPSの動画・連続ACTデータではなく、無操作中の連続映像は保存しない。通信が遅れる場合は基板のタイムアウトで動きが途切れる可能性がある。記録する指令時刻の差から実効速度を調べられる。

## 検出特徴を作る

収集後、保存先を指定して実行する。ロボットは接続不要。収集中のCPU負荷を増やさないよう、検出は保存済み画像に対して後処理する。

```bash
uv run python vision/prepare_imitation.py data/imitation/保存先のエピソードID
```

既存YOLO11n（CPU、入力320、信頼度閾値0.25）で各画像を推論し、クラスごとに最大信頼度の1個を選ぶ。使用重みのSHA256も保存する。遮蔽時は検出なしのフラグを残し、前の検出で埋めない。

入力15項目：スポンジ・ターゲットの正規化中心座標4、信頼度2、検出有無2、台座・肩・肘・グリップの指令値/180の4、段階のone-hot3。

出力9クラス：台座±、肩±、肘±、グリッパー±、待機。通信失敗したサンプルは抽出から除外する。失敗・中断エピソードは残さず、特徴抽出も成功例だけを受け付ける。学習と評価はエピソード・配置単位で分ける。

## 記録しながら連続移動する方式

通常は「連続移動（長押し）」を使用する。基板のJOGを継続更新するので、撮影・保存のたびにSTOPを送らない。設定済みの指令速度を使い、モーターの速度設定自体は変更しない。「微調整（1°）」も選択できる。

各更新時に操作前の関節指令と最新の元画像を取得し、前区間の終了指令との差を `delta_deg`、区間時間を `interval_seconds` として保存する。画像・JSONの書き込みは別スレッドで行う。画面上の操作件数には保存待ちの区間を含むが、成功保存は全書き込みの完了を確認する。書き込み失敗時は成功保存を拒否する。

ボタンを離す・画面外へ出る・ウィンドウが非アクティブになると、送信中の要求が完了した後にSTOPを送る。ブラウザから更新が途絶えた場合は基板の既存250msタイムアウトでJOGが止まる。記録処理から自動で移動を継続するタイマーは持たない。保存キューが満杯の場合も停止する。

連続区間では操作量が変わるため、学習では方向9クラスだけでなく変化量・時間も扱う必要がある。全記録を1°操作として学習させない。以前のstep記録と `control_mode` で区別する。
