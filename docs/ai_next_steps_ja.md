# カメラ認識と、任意位置間のスポンジ搬送

更新：2026年10月30日。対象は既存の軽い白いスポンジ。ユーザーの希望に合わせ、固定A/B位置の動作選択案から「作業範囲内の任意位置から任意位置への搬送」へ変更する。旧A/B案は現行の完成目標ではない。

## 完成目標と最初の実装範囲

カメラでスポンジと黒い丸い置き場所の位置を見つけ、丸の上へ関節動作を計算して運ぶ。スポンジと置き場所は、検証済みの到達領域内で好きな位置に置けることを目指す。通常動作時にスポンジや机へ専用マークを付けることは必須にしない。

最初は「固定カメラ・平らな机・同じスポンジ1個と同じ黒い丸い置き場所1個・一定の高さ・スポンジの向きをそろえる・搬送対象以外の障害物なし・実機で確認した狭い到達領域」に限定する。任意位置とは、この条件と到達領域内の位置であり、空間内の任意の3次元位置や姿勢ではない。

2026年10月28日、箱の代わりに黒い丸い物を置き場所として使うことに決定。ユーザーが、スポンジを置ける大きさ、アームの到達、退避姿勢で両方が見えることを確認。置き先はこの丸の中心。画面クリックは通常運転に必要としない。丸の直径・厚さとスポンジの高さは事前に測る。箱の縁を越える処理は初期実装から外す。

## 必要な処理

```text
カメラ → スポンジと黒い置き場所の検出 → 画像上の位置
                              ↓
                    机上のロボット座標へ変換
                              ↓
置き場所の中心 → 接近・把持・持ち上げ・搬送・解放の目標位置
                              ↓
                     関節角度の計算と範囲確認
                              ↓
                      既存のUSB制御 → 実機
```

AIはスポンジ（sponge）と黒い置き場所（target）の2クラスを検出する。対象の外形へ枠を付け、枠の中心を最初の位置推定に使う。置く精度は、黒い丸の中心から十分な余裕を残せるかで評価する。画像上の位置をそのままサーボ角度として送らない。動作生成は当面、幾何学と校正に基づく制御として実装し、学習済みのVLAとは呼ばない。

## マークなしと校正の違い

運転中にマークを置かないことと、カメラとアームの位置関係を事前に調べることは両立する。固定カメラでも、画像上の位置と実際の距離・方向の対応は必要。

最初の校正では、実際に位置を測った点を画面上で指定するなどの方法を検討する。必要なら一時的な目印を使っても、運転時には外せる。具体的な校正方法はカメラ配置と機構を確認して決める。対象上面と机面の高さの差、レンズ歪みによる位置ずれにも対応する。

## 次に行う作業

1. カメラを固定し、手動で無理なく拾える作業領域を画面上で確認する。
2. リンク長・関節軸・サーボの回転方向と取り付けオフセットを確認する。特に肩・肘の機構と連動関係を図にする。
3. カメラの画像位置とアーム基準の机上座標を対応付ける。
4. 指先を机から離した状態で、指定した数点の上方へ動かす制御を実装・検証する。
5. スポンジと黒い置き場所の学習用データを用意して認識モデルを追加学習し、検出した座標を上記制御へつなぐ。
6. 把持高さと置き場所の厚さを考慮し、接近→把持→持ち上げ→丸の中心上方へ搬送→下降→解放→退避を統合する。

肩・肘の負荷や指令と実際の角度のずれがあるため、理論計算だけで把持精度を保証しない。学習した位置→角度の補間を使う案もあるが、教示データを集めた領域内に限定し、未検証の外挿を行わない。

## 最初の作業：画像収集

AI用にPython 3.12の仮想環境 `.venv-ai` を分ける。ロボット操作用の環境はそのまま使う。必要なライブラリは `requirements-vision.txt`。

1. WebカメラをUSB接続し、机を見下ろす位置に固定する。
2. アームは撮影中に動かさず、電源を外して支持する。
3. 実際に使う範囲にスポンジと黒い丸を置き、両方の位置を変えながら撮影する。画像収集のために物を動かすときはアームは動かさない。

```bash
.venv-ai/bin/python vision/collect_sponge.py --camera /dev/video2 --split train
```

内蔵カメラが映る場合は `--camera 1` や実際の `/dev/videoN` を指定する。画面をクリックしてフォーカスを当て、以下のキーを使う。

- S：画像を止め、枠付け画面へ進む。
- 1：スポンジ全体をドラッグで囲み、Enterでその枠を確定する。
- 2：黒い丸の外周全体をドラッグで囲み、Enterでその枠を確定する。印刷されたロゴだけを囲まない。
- 枠付け画面でもう一度Enter：画像と両方のラベルをまとめて保存する。
- 同じ数字キーで枠を付け直せる。Escでその画像を保存せず戻る。
- N：スポンジも黒い丸もない背景だけの画像を保存。どちらかが映っているときには使わない。
- 画像内に見えている対象はすべて囲む。同じ画像に両方映るなら両方を囲む。各クラス1個までを対象とする。
- Q：終了。

まず10枚保存し、画像・ラベルが正しいか確認してから、学習用60枚程度、別の撮影セッションで検証用20枚、最後の評価用20枚を初期目安にする。枚数だけで性能が保証されるわけではない。似た連続画像の量産を避け、位置・向き・照明の違いを含める。白い物体や手など、間違えそうな背景も含める。動画から連続フレームを抜いて無作為に分割するだけでは、評価が過大になりやすい。

検証用と評価用は、それぞれ起動し直して撮影する。

```bash
.venv-ai/bin/python vision/collect_sponge.py --camera /dev/video2 --split val
.venv-ai/bin/python vision/collect_sponge.py --camera /dev/video2 --split test
```

`data/sponge/` に画像・YOLO形式の枠・撮影セッション記録・dataset.yamlを保存する。写真は外部送信しない。学習と検証に使用した写真を、最終評価用へ重複させない。

## この段階でできること・まだできないこと

2クラスの撮影・枠付けと、6モデルの20エポックの追加学習・検証・最終評価・保存まで確認済み。保存済みYOLO11nの重みをライブカメラへ接続済み。ユーザーが検出は概ね問題ないことを確認し、現在は机面の座標校正へ進んでいる。アームとの接続はまだ実装していない。旧1クラスの画像がある場合はラベル漏れを避けて再ラベル付けする。汎用COCOモデルの既知クラスには白いスポンジ専用クラスがないため、そのまま必ず認識するとは扱わない。

現在のサーボは実際の関節角度を返さないため、教示動作でも指令値と実位置のずれを考慮する。関節ごとの可動範囲、グリッパー50〜150度、ケーブル干渉と肩の発熱を引き続き確認する。

参考：[Ultralyticsの学習用データ形式](https://docs.ultralytics.com/datasets/detect/)、[COCOの検出クラス](https://docs.ultralytics.com/datasets/detect/coco/)
