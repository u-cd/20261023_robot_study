# 関節を選び、ボタンで操作する

ローカルのブラウザ画面から `arm_test` を操作します。Python標準のHTTPサーバーと、インストール済みのpyserialを使用します。インターネットや外部サービスは不要です。

## 1. 基板のコードを更新

CLI・IDE・操作画面のシリアル接続を終了します。アームを支持し、サーボ電源とUSBを外してから準備します。基板に旧コードがあるので、必要ならサーボを外して書き込みます。

プロジェクトルートで実行します。

```bash
.tools/arduino-cli compile \
  --fqbn arduino:avr:uno \
  --libraries /home/u/.arduino15/libraries \
  --build-path "$PWD/.build/arm_test" \
  firmware/arm_test

.tools/arduino-cli upload \
  --fqbn arduino:avr:uno \
  --port /dev/ttyUSB0 \
  --input-dir "$PWD/.build/arm_test" \
  firmware/arm_test
```

## 2. 操作画面を起動

CLIのシリアルモニタは開かず、次を実行します。

```bash
python3 control/arm_panel.py
```

ブラウザで <http://127.0.0.1:8765> を開きます。接続ボタンを押すまでは基板へ接続しません。サーバーは同じPC内からのみ接続できます。

## 3. 操作

開始角度の初期値は、ユーザー指定の台座90度・肩0度・肘0度・手首80度・グリッパー90度です。画面の入力欄の初期値であり、接続時に自動で姿勢へ移動する設定ではありません。各列の「有効にする」でその関節へ初めて指令します。肩・肘の0度はこの実機の取り付けに対する指令値で、一般的な直立・水平を意味しません。

1. アームを支持してから「接続」を押します。ポート接続で基板が通常リセットされ、保持が解除されます。
2. 横並びの5列から操作したい関節の列を確認し、その列で確認済みの開始角度を入力します。
3. その列の「有効にする」を押すと、その角度へ指令します。現在角度は不明なので、この最初の動きは急になる場合があります。
4. 角度表示の上の▲で角度を増やし、下の▼で減らします。クリックすると1度ずつ変わります。長押しは0.3秒後に連続動作へ切り替わります。
5. ボタンを離す、ボタンの領域から出る、画面のフォーカスが外れると連続移動指令を停止します。

移動の指令速度は関節ごとに変更できます。各関節の列の「指令速度」から約12・25・50・100度/秒を選び「速度を適用」を押します。初期値は従来と同じ25度/秒。速度変更時にはその関節の移動目標を解除し、変更だけでは動きません。最初のSTARTの急な移動には適用されません。非常に速い連打は基板側で間引かれます。表示角度・速度は指令値で、実際の角度・速度を測った値ではありません。

別の列の矢印を操作しても、既に有効な他関節は保持を継続します。長押し中は他の関節の矢印を無効にし、同時に動かす関節を1つに限定します。狭い画面では5列を横スクロールできます。複数サーボを保持するには適合する電源が必要です。給電が未確認なら、電源を外して1個ずつ接続して試します。

## 範囲と停止

- 関節1〜4：入力上は0〜180度。機構の通常使用範囲は未校正です。
- 関節5：実機報告に合わせ暫定50〜150度。端には余裕を残します。
- 「停止・保持」：全関節の目標を直前の指令値に変更します。電源遮断ではありません。
- 「この関節の保持を解除」：選択関節への信号を止めます。肩・肘は落下する可能性があるため先に支持します。
- 通信が途絶えると250msで長押し動作指令が止まります。物理的な即時停止や衝突検出ではありません。
- ターミナルでCtrl+Cを押すとサーバーを終了します。正常終了時はSTOPを送りますが、保持やサーボ電源は解除しません。

肩・肘の動作不良とケーブル干渉は未解決なので、過負荷・巻き込みを避けて試します。

## 新しいシリアルコマンド

従来のSTART・MOVE・STOP等も利用可能です。画面操作には以下を追加しています。

```text
STEP 1 +     台座を1度増やす
STEP 1 -     台座を1度減らす
JOG 1 +      台座を増加方向へ連続操作（250ms以内に更新が必要）
SPEED 2 50   肩の指令速度を50度/秒に変更（移動せず、保留目標を解除）
STOP         全関節の移動指令停止・保持
```

画面は基板の `ARM_TEST_V3` 起動メッセージで新版を確認します。旧版しかない場合は接続を拒否し、動作指令を送りません。更新後はPythonサーバーを再起動し、ブラウザを再読み込みしてください。再接続で保持が解除されるため、先にアームを支持します。

## 肩の発熱と速度比較

関節2が非常に熱くなるという報告があります。発熱中は動作や保持を続けず、アームを支持してUSB・サーボ電源を外し、十分冷ましてください。STOPは保持を続けるため、過負荷時の冷却手段にはなりません。

冷却後、まずケーブルの引っ掛かり・軸の締め過ぎ・部品接触を確認します。アームを伸ばし切らず、肩から先の重心を肩へ近づけた姿勢にし、適切な支持で負荷を軽減してから短い角度範囲で25度/秒と50度/秒を比較します。最初から100度/秒や大きな往復にはしません。実際の移動量、異音、発熱の再発を記録し、再発したら中止します。

速度を上げても静的な重量を支える能力は増えません。小さな目標差で動きにくかった場合は変化する可能性がありますが、指令だけが先行して急に追い付く動作にも注意します。

機械側の改善候補は、(1)到達距離や先端重量を減らす、(2)肩を助けるバネ・カウンターウェイトを設計する、(3)関節・基板・電源との適合を確認して高トルクサーボへ変更する、です。バネや錘は他姿勢の負荷や衝突も変えるため、取り付け前に機構を検討します。
