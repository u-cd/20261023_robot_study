# 学習済みモデルでWebカメラを認識する

2026年10月30日。最初の工程は、スポンジと黒い置き場所の検出枠・中心座標をリアルタイム表示すること。使用モデルは、既存60枚を36/12/12枚に分けて20エポック学習したYOLO11nの `best.pt`。アームへの指令送信は行わない。

## 起動

プロジェクトのターミナルから実行する。

```bash
.venv-ai/bin/python vision/live_detect.py
```

EMEET Webカメラを固定IDで選ぶため、USB接続によってデバイス番号が変わっても対応できる。明示する場合は次のように指定する。

```bash
.venv-ai/bin/python vision/live_detect.py --camera /dev/video2
```

別の撮影アプリで同じカメラを使っている場合は、そのアプリを終了する。

## 表示と操作

- 緑の枠：スポンジ（sponge）。オレンジの枠：置き場所（target）。十字は検出枠の中心。
- 名前の横の数値：信頼度と中心の `(x, y)` ピクセル座標。画像の左上が原点、右へxが増え、下へyが増える。
- 座標は元のカメラ画像に対応する。表示ウィンドウの拡大率や上部の情報欄は座標に含めない。
- `ONE EACH`：各対象を1個ずつ検出。`MISSING`：対象が不足。`MULTIPLE`：同じ種類を複数検出。
- 画面にフォーカスを当てて **S**：そのフレームの画像・検出結果を保存。**Q / Esc** またはウィンドウを閉じる：終了。ターミナルのCtrl+Cでも終了できる。

保存先は `runs/live_vision/`。`*_raw.jpg` は元画像、`*_overlay.jpg` は検出枠付き、同じ名前のJSONに中心座標・枠・信頼度・画像サイズ・モデル・撮影日時を記録する。保存画像は自動で学習データへ追加しない。

## この画面で確認すること

1. スポンジと黒い丸を1つずつ置き、枠と十字がそれぞれに付くことを確認する。
2. スポンジ、黒い丸をそれぞれ手で移動し、枠と座標が追いかけるかを見る。
3. 対象を画面外へ出し、古い枠が残らず `MISSING` になるかを見る。戻したときに再検出するかも確認する。
4. 間違った枠や見失う場所があればSで保存する。これは後の追加撮影・再学習の材料になる。

中心座標は検出枠の中心であり、まだ机上のmm座標や把持位置ではない。対象の高さやカメラの傾きによるずれは、次の座標校正で扱う。次工程に進む際はカメラとアームの台座を固定する。

## 実施した確認

実カメラで30フレームのCPU推論を完了。最後の保存フレームでスポンジ1個・置き場所1個を検出し、枠と中心の描画を確認した。元画像は640×480、推論入力は320、信頼度の下限は0.25、CPUスレッド数は4。その後、ユーザーが実画面の検出は概ね問題ないことを確認した。

画面を出さず、取得・推論・保存だけを確認するコマンド：

```bash
.venv-ai/bin/python vision/live_detect.py --headless --frames 30 --save-last
```

次は画像のピクセル座標と、アームを基準にした机上の実測座標の対応を取る。その後、関節の寸法・回転方向・取り付け角度を確認して、目標位置から関節角度を計算する。

机上のmm座標への変換は[座標校正の手順](table_calibration_ja.md)を参照。
