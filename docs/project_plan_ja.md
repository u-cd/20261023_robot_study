# ロボットアーム開発計画書

作成日：2026年10月23日 / 状態：初稿・機材未決定

## 1. 目的

初めてのロボット製作として、机上の色付きブロックを検出して指定位置へ運ぶロボットアームを開発する。制御・座標変換・運動学を理解して実装し、実機動画、設計資料、実験結果をGitHubで公開する。

リポジトリ：<https://github.com/u-cd/20261023_robot_study>

## 2. 計画の前提

- 機構とサーボは既存キットを活用し、ソフトウェアと校正を学習の中心にする。
- アーム4関節（台座・肩・肘・手首の傾き）＋独立したグリッパーを希望構成とする。最終的な関節モデルは購入機材の実構造に合わせる。
- PCは既存のものを使用する。OS、Python経験、電子工作経験は未確認。
- 予算は元の提案にある2〜3万円を仮目標、5万円を仮上限とする。本人の確定予算ではない。
- 7日間は部品到着後の集中開発案とし、配送日数は含めない。初心者向けには2〜4週間への分散も想定する。
- 最初はPython・OpenCV・USBシリアル通信を使う。ROS 2とPyTorchは基礎動作完成後に追加する。

## 3. 完成目標

| 段階 | 作るもの | 完成基準 |
| --- | --- | --- |
| A：最小構成 | 固定位置のブロックを固定位置へ運ぶ | 低速で動作し、同じ条件の10試行中5回以上成功する |
| B：本プロジェクトの目標 | カメラで位置を検出して運ぶ | あらかじめ定めた作業領域内の5地点で各2試行し、成功数・失敗理由を記録する。初期目標は5/10以上 |
| C：発展 | 模倣学習モデルと従来制御を比較 | 未学習の位置で成功率・所要時間を測定し、従来制御との差を説明できる |

成功とは「ブロックを持ち上げ、指定した置き場の内部へ移動し、離した後も置き場に残ること」とする。置き場の寸法、ブロックの寸法・重量、試験地点、照明条件を実験前に記録する。10試行は初期評価であり、高い信頼性の証明には使わない。

## 4. 最初の対象タスク

単色背景、固定カメラ、同じ高さの軽いブロック1個から始める。物体の回転方向は固定し、積み重ね・任意姿勢・動いている対象は後回しにする。カメラは作業面を見下ろす位置に固定する。

```text
USBカメラ → 色領域検出 → テーブル上の座標(mm)
                               ↓
                         把持動作の状態管理
                               ↓
                     逆運動学 → 関節制限の確認
                               ↓
                  USB通信 → 制御基板 → サーボ
```

動作は「待機 → 検出 → 上方へ接近 → 下降 → 把持 → 持ち上げ → 搬送 → 下降 → 解放 → 退避」とする。最初は各工程を手動で確認してから連続実行する。

## 5. 実装する内容

### 制御と通信

関節ごとのゼロ点、回転方向、角度範囲、速度上限を設定ファイルに保存する。PCからの指令には応答・タイムアウトを設け、異常時に次の動作へ進まない。電源投入直後の姿勢と、電源を切ったときのアームの落下にも対応する。

PWMサーボでは、指令角度と実際の角度を区別する。実測フィードバックがない場合、ログにも「指令値」と明記する。既製ファームウェアを使用した部分と、自作した部分はREADMEで分けて説明する。

### 順運動学・逆運動学

リンク長、肩の高さ、手首と指先のオフセットを測定し、座標系を図にする。単位は距離mm、内部の角度radに統一する。可動範囲外、到達不能な点、関節制限違反を検出する。逆運動学の結果を順運動学に戻し、目標位置と一致するか確認する。

台座＋肩＋肘＋手首ピッチの構造では、希望する指先の傾きから手首中心を求め、肩・肘の2リンク問題を解く。購入機材が別構造なら、このモデルをそのまま流用しない。

### 画像処理と校正

HSVによる色領域抽出と輪郭検出から開始する。既知の平面上の4点以上を使い、ピクセル座標からロボット基準のテーブル座標へ変換する。校正に使わなかった点で誤差を測る。

ホモグラフィは同一平面の変換なので、ブロック上面とテーブル面の高さの違いは誤差になる。対象の高さを固定し、必要なら対象高さの平面で校正する。レンズ歪みが大きい場合は歪み補正も行う。カメラを動かしたら再校正する。

## 6. 部品到着後の7日間案

1日約5時間、合計約35時間の仮計画。到達条件を満たさなければ、その工程を翌日へ繰り越す。

| 日 | 作業 | その日の確認結果 |
| --- | --- | --- |
| 1 | 部品確認、説明書確認、単体サーボ試験、機構組立 | 中立位置と機械的な制限を把握する |
| 2 | 電源・通信・関節校正、速度制限、停止処理 | 各関節を低速で個別操作できる |
| 3 | 固定姿勢列で把持・搬送 | 段階Aを評価し、動画を残す |
| 4 | 寸法測定、座標系、順運動学・逆運動学 | 到達できる点とできない点を判定できる |
| 5 | カメラ固定、色検出、平面校正 | 校正外の点の座標誤差を記録する |
| 6 | 画像処理と制御を統合、失敗時の中断 | 複数位置から自動で搬送できる |
| 7 | 10試行評価、原因分析、README・動画整理 | 実績と未達項目を説明して公開できる |

初心者向けに分散する場合は、第1週に組立と手動制御、第2週に固定位置搬送と運動学、第3週にカメラ統合、第4週に評価と資料整理を行う。AI学習は追加期間とする。

## 8. 停止と故障への備え

- 最初は無負荷・低速で1関節ずつ確認し、指や配線を可動部から離す。
- アームとカメラを固定し、机の端に物体が落ちない作業領域を設定する。
- 自動動作前に角度・速度・作業領域の制限と、容易に操作できる電源遮断手段を確認する。
- ソフトウェアの停止キーだけに依存しない。電源遮断時にアームが倒れる可能性も考慮する。
- サーボ電源の電圧・電流・極性・コネクタは、購入機材の説明書に合わせる。PCのUSBだけで多関節を駆動する前提にしない。
- 過熱、異音、通信断、繰り返す電源リセットが発生したら運転を止め、原因を確認する。

## 9. 発展：模倣学習

従来制御が動いた後に実施する。最初から画像・言語を直接入力するVLAは目標に含めない。

入力候補は物体座標、搬送先、関節状態、グリッパー状態、動作フェーズ。出力候補は小さな関節角度差とグリッパー操作とする。実測できない関節角度は指令値であることを明記する。

従来制御や手動操作から動作列を収集し、軌道単位で学習用と評価用を分割する。連続フレームを無作為に分割して同じ動作が両方に混入することを避ける。未学習位置で評価し、予測した角度差にも速度・関節制限を適用する。学習モデルで性能が改善しなくても、その結果と原因を記録する。

## 10. ポートフォリオ成果物

- 30〜90秒の実機デモ動画と、検出・座標表示の画面。
- 構成図、配線図、部品表、座標系とリンク寸法。
- 環境構築・校正・実行・停止方法を記載したREADME。
- 試行ログ：試行ID、対象位置、成功/失敗、所要時間、失敗理由。
- 失敗分析：検出、座標変換、位置ずれ、把持、電源・通信のどこで失敗したか。
- 自作範囲、利用ライブラリ、参考実装とそのライセンスの記録。

将来のディレクトリ構成案：

```text
docs/             計画・配線・校正・評価
firmware/         自作する場合のマイコンコード
control/          通信・運動学・動作管理
vision/           検出・カメラ校正
config/           リンク寸法・関節制限
experiments/      評価用スクリプト・小さな結果ファイル
learning/         後から追加する模倣学習
```
