## 実機での気づき・希望（ユーザー申告）

### 高さとグリッパー

- **把持高さは入力上5mmがよい。解放高さも5mmがよい。** 以前の仮値15mmより実機に合った。モデルに入力する値であり、実測の絶対高さ5mmを保証するものではない。
- 把持時のグリッパー角は最大150度である必要はない。スポンジを保持できる適切な角度を探す。新しい閉角度の確定値はまだ記録していない。

### 関節を動かす順序と速度

- 1関節ずつ順番に動かす方がよい。
- **下がるとき：台座 → 肘 → 肩。**
- **上がるとき：肩 → 肘 → 台座（下がるときの逆順）。**
- 現在の全体的な動きは遅すぎて、ぎこちなく感じる。速度を調節する必要がある。
- サーボの指令速度だけでなく、1度刻みの送信・応答待ち・中間点の刻み方による遅さも切り分ける。上記の希望順序は記録したが、現行の搬送処理へはまだ反映していない。

### 認識と動作範囲

- スポンジとターゲットの位置は、手動クリックではなく**検出モデルの結果から取得するべき**。
- 格子の外側も、ホモグラフィーを延長してある程度対応したい。
- まずアームが拾える範囲を調べ、現在のホモグラフィーの座標と対応づけるべき。
- カメラの座標変換を延長できる範囲と、アームが実際に把持・搬送できる範囲は別々に記録する。格子の外側の変換精度と実機到達性は未検証。現行の11点の凸包制限はまだ変更していない。

### アーム位置の計算と追加データ

- 関節角と実際の先端位置の関係は、点数を増やして誤差を減らす必要がある。
- 計算式そのものを確認し、もっと単純な表現で足りないか見直したい。
- 次回の追加点は格子の交点に限定せず、**実際にスポンジとターゲットを置き、手動操作でつかめる姿勢を作り、その関節指令と物体位置を記録して関係を逆算する**方法を試したい。
- 実際の把持を使う方が、タスクに合い、精度も改善するのではないかというユーザーの考え。
- 高さは目視で一定に保って収集し、その一定高さの平面では高さを独立に求めず扱う案。これは今後試す仮説であり、未実装・未評価。
- 把持用の一定高さと、持ち上げ・搬送用の高さは区別する。一定高さで集めたデータだけで高さ方向全体の精度が確定するとは扱わない。

## サーバーの終了方法

1. 動作ボタンを離し、動きが止まったことを確認する。必要なら「全関節 停止・保持」を押す。
2. `vision/arm_camera_panel.py` を実行しているターミナルで **Ctrl+C**。カメラと8766番の映像サーバーが終了する。
3. `control/arm_panel.py` を実行している別のターミナルでも **Ctrl+C**。8765番のアーム操作サーバーが終了する。
4. サーバー終了だけではサーボの保持解除・電源断にはならない。アームを手で支持してから、USBや外部電源を外す。電源を切ると肩・肘が下がる場合がある。

端末が見つからない場合は、まず次で対象を確認する。

```bash
pgrep -af '[v]ision/arm_camera_panel.py|[c]ontrol/arm_panel.py'
```

確認した対象だけ `kill PID` で終了できる。ただし通常は上記の各ターミナルでCtrl+Cを使う。今回はユーザーが終了方法を求めたため、こちらからサーバーを停止する操作は行っていない。
