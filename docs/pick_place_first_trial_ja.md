## 操作

1. <http://127.0.0.1:8766> を再読み込みし、「スポンジをつかんでターゲットへ運ぶ」を開く。
2. 「映像で把持位置を指定」を押し、スポンジ中心の真下にある紙面位置をクリックする。上面の中心では高さによる画像のずれが入る。クリックが難しい場合は格子から読んだXYを直接入力する。
3. 「映像で置き先を指定」を押し、ターゲット中心をクリックする。撮影時の参考値は約 (31,89)mm。ただし物体を動かした場合は再指定する。
4. 初期候補は把持Z=15mm、搬送Z=40mm、解放Z=15mm。これは測定済み高さではなく試行用の仮値。スポンジの厚みとグリッパーの接触位置に応じて変更する。
5. 「搬送候補を計算」を押す。この操作では動かない。11点の囲む領域外や、解がない位置は拒否する。
6. 実機の前で確認欄をチェックし、「押している間、この段階へ進む」を押す。離すと追加指令が止まる。送信済みの1°は完了する場合がある。
7. 各段階で実機の状態を確認し、「この段階の状態と写真を保存」。把持・持ち上げなどができたことを確認して「次の段階へ」。指令角到達だけで物体を持てたとは判定しない。

肩の力不足、ケーブルの引っかかり、机や物体への接触があれば離して止める。段階間の自動実行はしない。グリッパーの仮値は開60度・閉150度、手首80度固定。

## 候補の一例

以下は把持位置を (15,135)mm、置き先を (30,90)mm とした**計算例**。現在のスポンジが (15,135)mm にあると判断したものではない。実際には現在のスポンジとターゲットの位置を指定する。

| 段階 | XYZ [mm] | 台座・肩・肘・手首・グリップ [度] |
| --- | --- | --- |
| 現在位置から上昇 | 約15,135,40 | 93,125,65,80,150 |
| スポンジの上へ | 15,135,40 | 93,126,65,80,150 |
| 開く | 15,135,40 | 93,126,65,80,60 |
| 把持高さへ | 15,135,15 | 93,136,62,80,60 |
| つかむ | 15,135,15 | 93,136,62,80,150 |
| 持ち上げる | 15,135,40 | 93,126,65,80,150 |
| ターゲット上へ | 30,90,40 | 72,136,82,80,150 |
| 解放高さへ | 30,90,15 | 72,145,79,80,150 |
| 放す | 30,90,15 | 72,145,79,80,60 |
| 上へ退避 | 30,90,40 | 72,136,82,80,60 |

各位置間はモデルの直線経路を5mm以下の間隔で逆計算し、それぞれの角度へ1関節ずつ1度刻みで近づける。**関節を順番に動かす実際の軌跡は厳密な直線ではない。** 高さ方向のモデル誤差、障害物、開いたグリッパーの把持中心は未検証であり、実機確認を置き換えない。

## 記録と再計算

計画ごとに `runs/pick_place/計画ID/` を作成する。

- `plan.json`：座標、高さ、初期指令、10段階の角度と中間点、モデルのハッシュ。
- `setup.png`：計算時の最新カメラ画像。
- `stage_番号/日時/`：各段階で保存した元画像、目標入り画像、指令状態。把持成否や実測誤差の値は自動では付けない。

実サーバーで計算・写真保存だけ確認した計画：`runs/pick_place/20261030T151328_650808Z/`。計算例として保存したもの。

ターミナルで候補だけ計算する場合：

```bash
uv run python -m control.pick_place_plan \
  --pick 15 135 --place 30 90 \
  --current 93 144 63 80 150 \
  --pick-z 15 --travel-z 40 --release-z 15
```

このコマンドは計算のみで、アームには接続しない。画面の座標指定は最初の搬送動作を検証するための手動指定であり、AIによる自動検出からの搬送はまだ接続していない。
