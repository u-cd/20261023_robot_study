# 次回：動作工程を設計してから学習データを作り直す

更新：2026年10月31日。ユーザーは詳細な検討を後日に回す。**次回は、各動作をどう分け、何をルール・学習・人の確認に任せるかを固め、その設計に合わせて教師データを作り直す。** 今回これ以上の再収集・再学習は行わない。

## 今回までの結果

- 成功27試行・4,534操作区間から、小型BCモデルを学習した。検出位置＋関節指令＋3段階の入力で、次の操作と角度量を予測する。
- 未使用4試行の操作一致率は52.5%。これは実機の搬送成功率ではない。
- 最大予測の連続実行では、台座が選ばれ続ける問題があった。
- 成功例から画像位置→台座の目標角度を回帰し、台座と肩・肘の操作順を固定した。ユーザーから「わりとうまくできた」と報告があった。
- 続いてグリップの開閉も独立させる8区分を実装・反映した。**この最新の8区分については、まだ実機結果の報告を受けていない。**
- 完全自律の段階判断・高さ測定・把持成否判定は実装していない。手動確認を使う方式で当面よいという方針。

## 現在の8区分（次回の検討のたたき台）

1. 台座でスポンジの方向へ合わせる。
2. 肩・肘で把持位置へ合わせる。
3. グリップを閉じてつかむ。
4. 肩・肘で持ち上げる。
5. 台座でcoinの方向へ合わせる。
6. 肩・肘で置く位置へ合わせる。
7. グリップを開いて離す。
8. 肩・肘で退避する。

これは現行制御の区分であり、**8個の別モデルを作ることや、この区分を最終設計にすることが決まったわけではない。**

## 次回に固めること

各工程について、次の項目を決めてから収集UIとデータ形式を更新する。

- その工程の目的、開始条件、完了条件。
- 動かす関節、固定する関節、許可する方向。
- AIで選ぶ部分と、固定動作・ルールで処理する部分。
- モデルの入力と正解。次の操作を学ぶか、最終目標の関節角度を学ぶか。
- グリップの開閉角度、把持・解放の高さ、持ち上げ・退避姿勢などを固定できる範囲。
- 人が確認ボタンを押す境界と、自動で判断する境界。
- 開始姿勢やスポンジ・coinの配置をどの範囲で変えて記録するか。
- 工程別の評価と、実際にスポンジをつかんで運べるかの評価。

「画像位置から把持・配置姿勢を予測し、順序は固定する」姿勢回帰も比較候補。アーム寸法から逆運動学を解く方式とは区別する。現行BCにルールを重ねる方式を続けるかは、工程設計をしてから判断する。

## データ作り直しの方針

1. 工程設計を先に決める。現行の3段階ラベルで同じ収集を続けることを既定路線にしない。
2. 工程IDと開始・終了のイベントを、画像・関節指令・操作・時刻と一緒に記録できるようにする。
3. 人が操作する動きと、実行時のルール制約・順序を揃える。
4. 少数試行を保存して、画像・ラベル・完了境界が意図通りかを目視確認する。
5. 形式が固まったら、必要な配置・姿勢で成功例を集め直す。
6. 学習・評価を試行／配置単位で分けて比較する。

**既存データは削除しない。** 操作関節や段階境界から再ラベルして使える部分、把持・解放時の姿勢を抽出できる部分を先に確認する。既存の全フレームを、新しい工程の確定ラベルへ機械的に置き換えられるとは限らない。

成功例だけを残し、失敗・中断は破棄するというユーザーの方針を継続する。開始姿勢、各操作前後の関節指令、元画像、検出結果との対応を残す。関節値は実測角度ではなく指令値である。
