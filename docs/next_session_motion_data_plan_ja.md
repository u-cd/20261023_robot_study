# 次回最優先：実操作の生データを蓄積し、工程別データは後処理で作る

更新：2026年10月31日。**作業を再開したら、最初に以下の方針をユーザーへリマインドする。**

> 人が何度も実際にアームを操作した生データを十分に保存する。工程別・関節別の学習データは、その生データから後処理で整形する。工程の分け方が変わるたびに、元の記録を捨てたり収集し直したりする前提にしない。

これは、直前の「工程を固めて、その工程専用のデータを集め直す」という方針への重要な補足・優先順位の更新。工程設計は検討するが、**元データの保存と、モデル用データの整形を分ける**。現在の8区分を、生データ収集時の必須操作順や不可逆なデータ形式にしない。

## 生データの保存と派生データ

- 人が実際に行った操作、元画像／映像、取得・指令時刻、全関節の指令値・速度・保持状態、開始条件、試行IDを対応づけて残す。関節値は実測角度ではなく指令値。
- 工程境界・イベント・成功結果は、元の記録と対応する追加情報として保持する。
- 検出結果・工程ラベル・関節別の切り出し・正規化・学習用の分割は派生物として別に作る。元画像に検出枠を焼き込んだものだけを残さない。
- 元記録を上書きせず、後から違う工程定義・モデル・入力形式を試せるようにする。既存の27試行もローカルに保持する。
- 生データはGit管理外でローカル保管する。Gitへ画像・操作ログ一式を戻すという意味ではない。データのバックアップは別途考える。
- 現行記録は操作区間に対応した静止画像列で、無操作中も含む全時間の連続映像ではない。次回は「生データとして何を、どの周期で、どう時刻を合わせて残すか」を確認する。
- 失敗・中断の破棄という以前の指定は、今回明示的に変更されていない。勝手に挙動は変えず、保存対象を広げるかは必要に応じて次回相談する。

今回これ以上の再収集・再学習は行わない。

## 今回までの結果

- 成功27試行・4,534操作区間から、小型BCモデルを学習した。検出位置＋関節指令＋3段階の入力で、次の操作と角度量を予測する。
- 未使用4試行の操作一致率は52.5%。これは実機の搬送成功率ではない。
- 最大予測の連続実行では、台座が選ばれ続ける問題があった。
- 成功例から画像位置→台座の目標角度を回帰し、台座と肩・肘の操作順を固定した。ユーザーから「わりとうまくできた」と報告があった。
- 続いてグリップの開閉も独立させる8区分を実装・反映した。**この最新の8区分については、まだ実機結果の報告を受けていない。**
- 完全自律の段階判断・高さ測定・把持成否判定は実装していない。手動確認を使う方式で当面よいという方針。

## 現在の8区分（次回の検討のたたき台）

1. 台座でスポンジの方向へ合わせる。
2. 肩・肘で把持位置へ合わせる。
3. グリップを閉じてつかむ。
4. 肩・肘で持ち上げる。
5. 台座でcoinの方向へ合わせる。
6. 肩・肘で置く位置へ合わせる。
7. グリップを開いて離す。
8. 肩・肘で退避する。

これは現行制御の区分であり、**8個の別モデルを作ることや、この区分を最終設計にすることが決まったわけではない。**

## 次回に固めること

各工程について、次の項目を決めてから収集UIとデータ形式を更新する。

- その工程の目的、開始条件、完了条件。
- 動かす関節、固定する関節、許可する方向。
- AIで選ぶ部分と、固定動作・ルールで処理する部分。
- モデルの入力と正解。次の操作を学ぶか、最終目標の関節角度を学ぶか。
- グリップの開閉角度、把持・解放の高さ、持ち上げ・退避姿勢などを固定できる範囲。
- 人が確認ボタンを押す境界と、自動で判断する境界。
- 開始姿勢やスポンジ・coinの配置をどの範囲で変えて記録するか。
- 工程別の評価と、実際にスポンジをつかんで運べるかの評価。

「画像位置から把持・配置姿勢を予測し、順序は固定する」姿勢回帰も比較候補。アーム寸法から逆運動学を解く方式とは区別する。現行BCにルールを重ねる方式を続けるかは、工程設計をしてから判断する。

## 次回の進め方

1. **最初に、生の実操作を十分に蓄積し、後処理で工程別・関節別のデータを作る方針をリマインドする。**
2. 現在の生記録で保存できている情報と、不足する情報・時間区間を確認する。
3. 工程の分け方、学習／ルール／人の判断の役割を検討する。生データは設計変更後も再利用できる形式にする。
4. 必要なら収集機能を改善し、少数試行で画像・操作・時刻の対応を確認してから実操作を繰り返し記録する。
5. 元記録を残したまま、工程別の教師データを派生生成する。既存記録の再ラベルで使える部分も調べる。
6. 学習・評価を試行／配置単位で分けて比較する。

既存の全フレームを新しい工程の確定ラベルへ自動で置き換えられるとは限らない。必要な確認・注釈を追加し、加工条件と元の試行・フレームとの対応を残す。
